# API 用量完整性防护（开发阶段）

## 本轮实施契约

先修复既有单 episode 计量，再设计跨进程累计预算。仅用离线响应回归，不请求真实服务。

1. token 数必须为非负整数，不能把 bool、负数、字符串、小数作为可信计数。
2. 允许只有有效 total 的响应；缺少 total 时，仅在 prompt/completion 都有效时求和。
   同时声明三项时必须满足 total = prompt + completion；部分分项也不能大于 total。
   畸形声明不转成零、不静默修正为另一套可信用量。
3. 用量不完整时，episode 汇总的相应总量为 null，同时保留已知小计与完整性标记。
   没有配置费率时费用未知，不代表免费。有效 token 不因费用未知而丢失。
4. 配置 token/费用预算后，无法核实对应计量或已经超额，就拒绝继续本 episode；
   后续 next_action 不能再发请求。显式 begin_episode 只能开始新 episode，不是跨批次预算重置授权。
5. 限额及费率拒绝 bool、非有限值及不合法类型；token 限额是正整数，费用限额为
   有限正数，费率是有限非负数。计费运算溢出也不作为可信金额。

## 不得扩大的结论

- 这是响应返回后的单 episode 防护；当前请求可能已产生超过阈值的费用，不能称硬性消费上限。
- 不实现跨进程预算预占、累计金额账本、进程崩溃对账或真实服务费用核验。
- chat preflight、HTTP 错误/自动 JSON 兼容回退及断网请求的潜在消费不纳入当前 episode
  完整计费保证；新费用账本必须统一覆盖这些路径。HTTP 成功响应中的 usage 也只是提供商声明。
- 金额是提供商声明的用量乘以配置费率的估算，不含另行收费项目，也不是供应商账单。
  费率的十进制表示先转为精确有理数计算，再输出有限浮点数；不依赖调用者 Decimal
  上下文。最终浮点转换/合计仍可能舍入，不能据此保证严格金额上限。
- 未配置预算的离线/兼容模式可以继续返回有效动作，但未知总量必须显式保留。
- 冻结正式协议及安全配置累计预算前，仍不运行真实研究实验。

## 汇总字段与生命周期

`usage_scope=next_action_success_responses` 明确这里只覆盖成功返回可解析响应的动作请求。
`total_tokens` / `cost_usd` 在该范围完整时才是数值，否则为 null；`known_tokens` /
`known_cost_usd` 是已知小计，不是完整账单，金额运算溢出也必须置 null。
`tokens_complete` / `cost_complete` 分别标记这两种完整性。
`calls` 保留本 episode 内已记录的响应数，`metered_calls` 仅计 next_action；
`requests` 包含逐响应计量。未发生请求时零是空集合小计，不表明调用过免费模型。

调用方必须在真正的新 episode 开始时调用 begin_episode，不能为了通过超额检查而重置。
当前旧 ExperimentRunner 有此生命周期；UnifiedEpisodeEngine 的真实模型生命周期接入仍需
独立验证，本轮不把脚本引擎自动称为已支持付费比较。重启进程也不能恢复本内存计数器。
