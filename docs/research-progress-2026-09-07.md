## 研究定位与文献核查

目标是完成可检验的研究问题和可靠实验，准备 SCIE 研究稿。现有软件与 DOI 作为
复现基础；JOSS 软件短文保留为单独路线，不作为 SCI 目标的替代。

本轮阅读以下原始论文摘要页面，属于定向检索，尚不是完整系统综述或新颖性证明：

| 来源 | 与本项目重叠 | 对研究设计的影响 |
|---|---|---|
| [ReliabilityBench, arXiv:2601.06112](https://arxiv.org/abs/2601.06112) | 重复运行、工具故障、终态等价、多模型与架构比较 | 不能把这些组合本身作为首次贡献 |
| [AgentCheck, arXiv:2607.11098v3](https://arxiv.org/abs/2607.11098v3) | 工具响应扰动、故障重放、缓解策略比较 | 需要明确超越已有重试/验证实验之处 |
| [When Tools Fail / ToolMaze, arXiv:2606.05806](https://arxiv.org/abs/2606.05806) | 动态重规划与错误恢复 | 必须纳入重规划基线，而非只比较强弱提示 |

提高有证据的完成率，同时避免重复副作用？这是待验证方向，暂不称为新算法。
后续还须全文检查、代码检查以及针对 idempotency/ambiguous commit 的补充检索。

## 本轮代码审计发现

1. 24 个任务实际来自 3 个 `family_id`，每模板 8 个变体。不能把它们解释为
   24 个完全独立任务结构，更不能把 864 次运行解释为 864 个独立样本。
2. 原 `timeout_committed_once` 给模型的报错文本直接透露“已提交”，与未执行超时
   不同。已修复为完全相同的模型可见超时观测，执行真值只保留在评估回执中。
3. 原提交后超时可能落在读取动作或被拒绝的操作上。现在只允许已知修改类工具
   的成功执行触发；统一引擎新增 `fault_actions` 策略并记录在封存元数据中。
   显式预先选择目标修改工具，使执行前/执行后两条件的动作资格一致。
   对未来新工具仍须人工核实成功回执是否真能证明持久提交。
4. 新增按冻结计划联接、按任务等权、整组重采样的分析模块。UNKNOWN 与未到达结果
   保留计划分母，另给未知结果的最不利/最有利范围；详见
   [分析说明](cluster-analysis.md)。现有统计功能尚不覆盖安全副作用与多重比较。
5. 文件系统异常现在不再把随机临时路径传入模型，减少两次运行间无关提示差异。
6. 当前引擎把多个 `V/T/H/C/R/G/E` 维度统一填成终态 outcome；这些不能被当成
   独立验证过的多维测量。后续须逐维实现证据规则，或从研究主张中移除这些维度。

这些修复改变了实验条件。旧数据仍是开发/探索资料，不能与新条件未经说明合并。

## 可复现的零成本工程例子

安装项目后，在仓库根目录运行：

```shell
python scripts/blinded_timeout_demo.py --output runs/blinded-timeout-demo
```

使用两个明确标为 scripted 的策略与两个超时条件，共 4 个 episode；不调用模型。
输出逐次证据、回执、封存清单，以及 `demo-summary.json`。脚本检查四次模型可见
首个超时观测相同，但评估真值不同。输出目录须为新目录，防止覆盖既有证据。
它证明工程行为，不证明真实模型能力、策略创新或论文效果。
